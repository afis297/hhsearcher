# hhsearcher — парсер вакансий hh.ru

[![License: CC BY-NC 4.0](https://img.shields.io/badge/License-CC_BY--NC_4.0-lightgrey.svg)](https://creativecommons.org/licenses/by-nc/4.0/)

Сбор вакансий с hh.ru в таблицы Excel, объединение выгрузок и извлечение
обязанностей через локальную LLM (Ollama).

## Структура

| Файл | Назначение |
|---|---|
| `main.py` | Лаунчер-меню для запуска остальных скриптов |
| `parser.py` | Парсер HTML + API: берёт ID вакансий со страниц поиска, детали грузит через API. Выдача как в браузере, но медленнее (обход капчи) |
| `parser2.py` | Парсер только через API: превращает ссылку поиска в запрос к API. Быстрый вариант, порядок выдачи — по логике API, а не сайта |
| `common.py` | Общий код парсеров: сеть с ретраями, конфиг, обработка вакансий, запись XLSX |
| `merger.py` | Объединение нескольких XLSX в одну таблицу (дедуп по ID) |
| `ollama_processing.py` | Извлечение обязанностей из описаний через локальную модель |
| `config.example.json` | Пример конфига — скопировать в `config.json` и вписать токен |

Колонки итоговой таблицы: №, ID, ссылка, название, дата публикации, описание,
обязанности, навыки, компания, город, график, зарплата.

## Требования

- Python 3.9+
- Установленная Ollama (только для `ollama_processing.py`): `winget install Ollama.Ollama`
- Модель: `ollama pull qwen2.5:7b` (ПК с GPU ~12 ГБ) или `ollama pull qwen2.5:1.5b` (GPU ~4 ГБ)

## Установка

```bash
pip install -r requirements.txt
cp config.example.json config.json
# вписать api_token с hh.ru в config.json
```

## Работа

1. Запустить `main.py`, выбрать нужный скрипт.
2. `parser.py` / `parser2.py`: согласиться с настройками из `config.json` (или ввести вручную),
   вставить ссылку поиска с hh.ru, дождаться конца — папка с готовой таблицей откроется сама.
3. `merger.py`: выбрать файлы для объединения, выбрать куда сохранить.
4. `ollama_processing.py`: выбрать модель, входной XLSX и имя выходного файла.

## Настройки config.json

- `max_vacancies` — максимум вакансий за запуск
- `start_page` — стартовая страница (оба парсера)
- `per_page` — вакансий на странице, только для `parser2.py` (больше 100 API не отдаёт)
- `verbose` — писать ли логи в файл (`true`/`false`), работает в обоих парсерах

## Примечания

- API отдаёт вакансии по своей логике, порядок может отличаться от сайта.
  Совпадения с выдачей сайта добивается связка HTML + API (`parser.py`).
- Regex-извлечение обязанностей в парсерах покрывает не все формулировки —
  для качества использовать `ollama_processing.py`.
- `parser.py` пропускает вакансии со статусом «Собеседование».
  Для страниц переговоров рядом положить `cookies.txt` (в git не коммитится).
